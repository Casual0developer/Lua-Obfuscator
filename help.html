How LuaVeil works

Scramble local names, encode constants, and condense the code while preserving its structure.

A local workspace for preparing and exporting your Lua source.
01

Names and layered constants

Local declarations and references get matching randomized names. Named functions are rewritten as assignments, allowing property names and implicit method parameters to be scrambled while keeping normal : calls. Supported integers from 0 through 2,147,483,647 can use randomized exact arithmetic; floating-point and larger literals stay intact.

Strings, table keys, and property names use packed records in a shuffled pool. Each constant gets independent parameters for one to four reversible layers, three arithmetic arrangements, three feedback modes, and optional reversal. The decoder's local names are randomized for every output.

The packing alphabet uses 64 randomized symbols drawn from printable ASCII characters 33–126. Encoded records use delimiter-safe Lua long strings. Byte checks detect malformed records and damaged decoded constants. These checks detect corruption; they are not cryptographic authentication and can be removed by someone editing the output.

The decoder works in place once per unique constant. Repeated access uses the cached pool. More layers add startup work. Empty pools generate no decoder. The target supplies string.byte, string.char, table.concat, and error. The decoder and parameters are included, so the encoding remains reversible.

02

Formatting and recovery

Valid Lua can always be formatted into multiple lines. Formatting does not restore discarded variable names or decode constants. An audit confirmed that extracting the shipped decoder initializer recovers the decoded constants. Runtime inspection can also observe them. Extra layers and randomized names increase representation complexity without making client code secret.

The Compact, Balanced, and Large presets choose different layer, junk, and padding sizes. Number masking and source-comment removal have separate controls. Single-line output also works with string encoding disabled and preserves string contents. Sensitive credentials and authorization decisions need protection outside the distributed script.

03

Your supplied watermark comments

-- This script was generated using MoonVeil 2.1.1 [https://moonveil.cc]
--[[ v1.0.0 https://wearedevs.net/obfuscator ]]
--[[ obfuscated @ discord.gg/25ms ]]

These exact supplied comments are added once when enabled. No extra watermark names are generated. The line comment needs a newline so it does not comment out the program; the code body can still occupy a single long line.

04

Larger output and symbol padding

The junk-block slider selects 0–128 isolated calculations, with 32 selected by default. The junk toggle controls those blocks.

Symbol padding is a separate size control from 0–2048 KB, with 512 KB selected by default. It inserts random printable symbols and spaces inside an inert Lua long comment. Padding increases the file's visual bulk without adding runtime work or extra security. It remains independent of the junk-block toggle.

The output page reports padding size and the complete UTF-8 file size so you can see the size cost before downloading.

05

Local processing

Your Lua source is parsed as UTF-8 text and processed in a background worker. The browser does not run the supplied Lua code. Processing can be cancelled and stops after 15 seconds. Files are limited to 1 MB and generated output to 8 MB.

The input draft and latest output are saved in this tab's session storage when available. If storage is blocked or full, the output remains available on the editor page for copying or downloading.

06

Compatibility

Modes cover Lua 5.1–5.3, LuaJIT, and a subset of Roblox Luau. The Luau mode recognizes compound assignments, contextual continue, floor division, and binary or separated numeric literals. Strings and comments are kept outside these syntax workarounds.

Luau type annotations, interpolated strings, if expressions, and Lua 5.4 attributes are not supported.

Each large Luau function can pack simple local declarations into its own private table. This includes nested functions, grouped declarations of up to 16 variables, and forward declarations. The usual target is 170 active locals for headroom; a parameter-heavy function can use up to the actual 200-local limit. Every generated function is checked against that strict limit, along with lexical capture limits. Standard Lua modes keep their lexical limits.

These targeted checks do not cover every compiler register limit or replace the official compiler. Code that inspects local names or depends on debug information can observe the transformation. A shebang is retained for multiline output and removed when producing a single-line code body. A full Lua VM wrapper is not included. Test generated output in the target environment.

07

Runtime speed

Preserve fast field access leaves property names and literal keys readable so Luau can retain its optimized field and builtin paths. Encoded strings used in loops can be cached in locals. Turning this option off selects full key encoding. This trades some name hiding for runtime speed.

Compact uses one layer, fast field access, no junk, no padding, and no integer masking. Balanced keeps three layers with fast access. Large enables full key encoding. Larger output and more layers add loading or startup cost. The decoder also needs table.unpack or unpack to build strings in batches.

The measured hot paths were mostly close to the original and up to 3.4 times faster than the previous obfuscator in the test suite. Constant decoding still adds startup work. The result page's build time measures browser processing, not the Lua script's runtime.
